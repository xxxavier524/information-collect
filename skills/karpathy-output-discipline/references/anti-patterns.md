# 表达反例清单

第 8 条"写人话"的展开。每条一个反例、一个改法。单独出现一次的弱信号不必改，几个一起出现才是问题；引用、标题、专有名词里的不动。

## 一、开场与收尾

| 反例 | 改法 |
|---|---|
| 好的！我来帮你看一下这个问题。 | 删。直接给结论。 |
| 这是一个非常好的问题。 | 删。 |
| 首先，让我们来理解一下背景…… | 删。用户知道背景。 |
| 希望以上内容对你有帮助！如有其他问题随时告诉我。 | 删。 |
| 我已经完成了 A、B、C 三项修改，这意味着现在…… | 删。改成"现在能做什么"的一句话，或者直接不说。 |
| Sure! I'd be happy to help. | 删。 |
| Let me know if you need anything else. | 删。 |

## 二、句式套路

| 反例 | 改法 |
|---|---|
| 这不是一个技术问题，而是一个流程问题。 | 这是流程问题：审批在部署之后才发生。 |
| 与其说是性能瓶颈，不如说是设计缺陷。 | 直接说是什么缺陷。 |
| 它快速、稳定、易扩展。（凑三项） | 有证据的写几项。只有"快"有数据，就只写"快：p99 从 800ms 降到 120ms"。 |
| ……这，才是真正的工程之道。（段尾金句） | 删。段落在最后一个事实处结束。 |
| 真正重要的是…… / 关键在于…… | 直接说那件重要的事。 |
| It's not a bug — it's a feature. | State what it does. |

## 三、空话与黑话

| 反例 | 改法 |
|---|---|
| 值得注意的是 / 需要指出的是 | 删，直接说。 |
| 综上所述 / 总而言之 / 总的来说 | 删。短回复不需要总结。 |
| 赋能、抓手、闭环、打通、链路、颗粒度 | 换成具体动作："让 X 能调用 Y"。 |
| 至关重要、革命性、全方位、深度、极致 | 删，或换成数字。 |
| 研究表明 / 业内普遍认为 | 给出处链接，没有就删。 |
| delve, leverage, robust, seamless, crucial | 换成普通词或删。 |

## 四、语气与确定性

| 反例 | 改法 |
|---|---|
| 现在应该可以了。 | 跑验证，然后："`npm test`：42 passed, 0 failed。" |
| 看起来没问题。 | 说检查了什么："读了 `auth.ts` 的 3 个调用点，都传了 token。" |
| 搞定！完美！🎉 | 删。说结果。 |
| 这可能也许会导致一些问题。 | 有把握："会导致 X"。没把握："不确定，取决于 Y，我没法在这里验证"。 |
| 哎呀，测试失败了。 | "`auth.spec.ts:42` 失败：期望 200，实际 401。原因：缺少 Authorization 头。" |

## 五、格式

| 反例 | 改法 |
|---|---|
| 每个列表项开头都加粗一个标签 | 只在需要扫读时加粗，一段最多一处。 |
| 三段话的回复加了四个标题 | 去掉标题。 |
| 满篇破折号连接句子 | 改成句号或逗号。 |
| 只有两项也做成表格 | 用一句话。 |
| 装饰性 emoji（✅🚀💡） | 删。状态标记只在清单里用。 |

## 六、技术内容

| 反例 | 改法 |
|---|---|
| 把报错"概括"成"出现了类型错误" | 原样引用最关键的一行：`TypeError: Cannot read properties of undefined (reading 'id')` |
| 路径写成"那个配置文件" | `config/database.yml:12` |
| 自造缩写：cfg、impl、fn | 写全：配置、实现、函数。 |
| 压缩时丢了否定词："迁移前备份" 写成 "迁移 备份" | 否定词、"只""除了"、数字单位一律保留。 |
