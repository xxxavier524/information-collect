# 3 级：交互 HTML

Karpathy："让模型'用 HTML'输出，得到一个漂亮的交互网页。"以及：现在可以要一个"大型、定制、用完即弃"的软件产物，这在以前根本不值得做。

页面的目的只有一个：让这一个读者弄懂这一个概念。它是一次性的，力气花在交互上，不花在工程化上。

## 页面结构

从 [`assets/explainer-template.html`](../assets/explainer-template.html) 开始。它已经有：浅色/深色主题、手机宽度可用的单栏布局、一个可运行的示例图（梯度下降 + 学习率滑块 + 逐步按钮）。替换内容，保留结构。

典型页面：

1. **标题和一句话总结。**
2. **简要版**：3～5 条要点，用受控文字写，就是提纲里的核心结论。
3. **每个机制步骤一节**：短文字，需要时配一个可交互的图。
4. **这页不能说明什么**：局限、原文里的"可能"、原文没回答的问题。情态在这里保持可见。

## 有用的交互

| 模式 | 什么时候用 | 例子 |
|---|---|---|
| 参数滑块 | 结果取决于某个数 | 学习率 → 梯度下降的路径 |
| 上一步/下一步 | 过程分成几个阶段 | 握手协议的每一轮 |
| 前后对比切换 | 变更、diff、修复 | 重构前后的代码，改动行高亮 |
| 悬停/点按显示 | 图很密，数值很多 | 热力图，点格子看数值 |
| 播放/暂停 | 随连续时间变化的过程 | 扩散过程里的粒子 |
| 先猜再揭晓 | 结果出人意料 | "先猜输出，再点开看" |

每个控件都要满足：
- 一动就有看得见的变化。计算很便宜时不要加"运行"按钮。
- 图下有一句说明文字，说当前设置展示的是什么，由 JS 跟着控件更新。
- 键盘和触屏都能操作。用原生 `<input type="range">` 和 `<button>`。
- 默认值展示典型情况。另加一个预设按钮展示有意思的边界情况（例如"学习率太大"）。

## 没用的交互

- 只是装饰的动画（滚动淡入、视差）。
- 控件动了，读者看不出有什么变化。
- 假装在模拟、其实播放固定脚本。页面说演示某个算法，就在 JS 里真的跑这个算法。

## 技术要求

- 一个 `.html` 文件，CSS 和 JS 内联。
- 外部库只在真能省事时用（数学公式用 KaTeX，复杂图表用 D3），只从 `cdnjs.cloudflare.com` 或 `cdn.jsdelivr.net` 加载。CDN 加载失败时，文字内容仍要能显示。
- canvas 按 `devicePixelRatio` 缩放，线条才清晰；窗口尺寸变化时重绘。
- 不加统计代码，不加会发送数据的表单。`localStorage` 只用来记住滑块位置这类小事，并且包在 `try/catch` 里。
- 有浏览器就打开检查，修掉控制台报错。
- 页面上的文字也要遵守严格度。可以把正文和说明文字抽出来，用 `scripts/ste-lint-zh.py` 或 `scripts/ste-lint.py` 检查。

## 页面上的数字

页面上每个数字只能是三种之一：现场算出来的、原文给的、标了"示例值"的。一个看起来像实测结果、其实是随手编的默认值，违反"不编造"。
