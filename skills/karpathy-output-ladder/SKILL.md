# Karpathy 四级输出

Karpathy 的判断：模型能独立干的活越来越多，人的工作会往上移，变成**监督和理解**模型的产出。好在代码和智能都越来越便宜，可以为理解一件事，临时做一个以前不值得做的、**用完就扔**的产物。

他给了四种格式，后一种通常比前一种更容易看懂：

| 级 | 格式 | 适合 |
|---|---|---|
| 1 | 受控文字（约 80% 的 ASD-STE100） | 短解释、diff、要反复读的答案 |
| 2 | 图（Mermaid 或 SVG） | 结构、数据流、调用顺序、对比 |
| 3 | 单文件交互 HTML | 有参数可调、有过程可逐步看、有"如果……会怎样" |
| 4 | 讲解视频（Manim + 旁白 + 配音） | 有前因后果、随时间变化的主题 |

为这一个读者、这一个主题做产物，不要做框架。

---

## 第 1 步：选级，定严格度

**用户点名了格式就用那个格式**：
- "解释""讲清楚""用 STE""说人话" → 1 级
- "画图""流程图""架构图""可视化" → 2 级
- "HTML""网页""可交互" → 3 级
- "视频""动画""3b1b""manim" → 4 级

**没点名就自己选**，并用一句话说明，例如：`用 3 级（HTML）：这个主题有一个可以拖动的参数。`
- 短解释、diff → 1 级
- 关系和结构是重点 → 2 级
- 有参数、有过程、需要"试一下" → 3 级
- 只有用户明确要视频才做 4 级，它最贵

**严格度**默认 80%，因为 Karpathy 自己说完整标准太严。用户说"严格 STE""完整 STE100"就用 100%，说"简单一点就行"就用 50%。严格度影响这次写的**所有**文字：正文、图上的标签、网页说明、视频旁白。

## 第 2 步：先写提纲，再动手

在动手做任何产物之前，先在内部写一个提纲（不用给用户看）：

1. **核心结论**：读者必须带走的 3～7 条事实。
2. **机制**：什么导致什么，按顺序。
3. **情态**：原文里每一个"可能""也许""尚不清楚"。
4. **一个例子**：用原文里真实的数字或名字。

四级产物都从同一份提纲出来。用户说"换成图看看"时，事实不变，只换形式。

### 两条铁律

**不编造。** 画图要给箭头写标签，做网页要给滑块设默认值，做视频要写过渡句，这些地方最容易顺手补一个原文没说的原因、数字或意图。不要补。确实需要示例值，就标明"示例值"。解释 diff 或文档时，每条结论都要能指回原文的某一行；原文没说为什么，就写"原文没说明原因"。

**保留情态。** "可能是竞态导致的"在任何一级都不能变成"是竞态导致的"。图里用虚线加"可能"，网页里写在说明文字里，视频里在旁白里说出来。置信度本身就是内容。

## 第 3 步：做产物

### 1 级：受控文字

- 第一句是一句话总结。然后用短段落或编号列表。比较才用表格。
- 术语第一次出现时用一句话定义，之后全文只用这一个叫法。
- 80% 严格度的核心规则：
  - 一句一个意思。说明句：英文 ≤25 词，中文 ≤40 字。操作步骤：英文 ≤20 词，中文 ≤25 字。
  - 主动语态，主语明确。
  - 不用分号。不用"进行分析"这类虚动词，直接写"分析"。
  - 不用营销词（无缝、强大、赋能、闭环、seamless、robust、powerful）。
  - 同一个东西全文一个名字，不轮换同义词。
  - 一段一个主题，最多 6 句。3 步以上用编号列表。
- 完整规则、严格度分档、中英文例子见 [references/controlled-writing.md](references/controlled-writing.md)。
- 写完跑 linter，修掉所有硬违规：

  ```bash
  python3 <skill目录>/scripts/ste-lint-zh.py explanation.md   # 中文
  python3 <skill目录>/scripts/ste-lint.py explanation.md      # 英文
  ```

  linter 永远不标记情态词。不要为了句长删掉"可能"，把句子拆开。

### 2 级：图

先读 [references/diagram.md](references/diagram.md)。

- 纯流程或调用顺序：直接在回复里给 Mermaid 代码块。
- 需要多个面板、标注、对比：生成一个自包含的 `.svg`。
- 箭头上写清楚传的是什么（请求、token、某个值）。没有标签的箭头只是装饰。
- 标签不超过 6 个词/12 个字，长内容放进"说明"面板。
- 原文不确定的关系画虚线，标"可能"。
- 原文没有的节点不画。

### 3 级：交互 HTML

先读 [references/html-explainer.md](references/html-explainer.md)，从 [assets/explainer-template.html](assets/explainer-template.html) 开始改。

- 一个文件，CSS 和 JS 内联。外部库只在真能省事时用，且只从 cdnjs 或 jsdelivr 加载；CDN 挂了，文字也要能显示。
- 交互要服务于理解：参数滑块、上一步/下一步、前后对比切换、先猜再揭晓。
- 每个控件一动，图上就有看得见的变化；图下的说明文字跟着更新。
- **真的算，不演**。页面说自己在演示梯度下降，页面里就要真的跑梯度下降。
- 页面末尾必须有"这页不能说明什么"一节：局限、情态、原文没回答的问题。
- 能开浏览器就打开检查，修掉控制台报错。

### 4 级：讲解视频

先读 [references/video.md](references/video.md)。

1. 写 `narration.md`：按"拍"编号，每拍 1～3 句受控文字，约 4～8 秒。整片 8～20 拍。
2. 写 Manim 场景，一拍对应一组动画。3b1b 风格：深色背景、一屏一个概念、用运动展示机制。
3. 配音：用户提供了 `ELEVENLABS_API_KEY` 就用 ElevenLabs；否则用本地 TTS（Piper、Kokoro、macOS `say`）。
4. 用 ffmpeg 合成音视频，抽两三帧检查有没有重叠、空白。

- **没有真的渲染出 mp4，就不能说"视频做好了"**。缺 Manim 或 TTS 时，交付分镜脚本（每拍：时长、画面、旁白、屏幕文字），并说明缺什么、怎么装。
- 不经用户同意，不在系统里全局安装软件，不下载语音模型。

## 第 4 步：交付

回复只包含三部分：

1. 选级说明（只有你自己选的级才写，一行）。
2. 1 级直接给正文；2～4 级给文件路径，加两句话说明它展示了什么。
3. **待核对清单**：产物里 3～7 条关键论断，每条注明对应原文的哪里。产物是看原文的一种视图，不是证据；压缩会丢信号，也会放大错误。

最后一行给出更高的级别作为下一步：

```
下一步可选：图（2）· HTML（3）· 视频（4）
```

只列比当前高的级。已经是 4 级，就提供"调整严格度"或"重做某一拍"。

产物默认存到当前项目的 `explainers/<主题>/` 下，用户指定了位置就用用户的。

不要加开场白、规则清单、结尾客套。用户问"为什么这样写"时再解释规则。

## 边界

- **不声称 ASD-STE100 合规。** 这里用的是标准的规则类别，不含 ASD 约 900 词的受控词表（标准免费下载但不可再分发）。80% 是风格要求，不是合规分数。用户要严格合规时，请用户去 [asd-ste100.org](https://www.asd-ste100.org/) 下载正式标准逐词核对。
- **形式改不了内容。** 原文本身没讲清楚的，就说没讲清楚，不要编一个看起来合理的机制填进去。
- **够清楚就停。** 目标是没有歧义，不是最短。
- **不用于**：营销和文学文案（受控写法会抹掉语气）；改写给其他 agent 读的工具描述、报错、prompt（那是改写，不是解释，可以只用 1 级的规则，直接给改写结果）。
